# UAT-M1-005 – Wiederholter Import, Idempotenz und öffentliche Aktualisierung

**GitHub-Test-Issue:** [#128](https://github.com/Studio-Animal-Aided-Design/habitat-database/issues/128)

**Ziel:** Gleicher Snapshot erzeugt keine Dubletten; geänderter Snapshot wird erst nach Commit sichtbar. **Bezug:** #76, #85, #107; M1-03/05. **Umgebung:** lokale Test-DB nach 003.

## Schritte und Soll-Ergebnis

1. Exakt dieselben CSVs erneut als Dry-run senden. **Erwartung:** keine fachlichen Änderungen im Diff; Fingerprint identisch.
2. Apply erneut bestätigen oder dokumentierte Duplicate-Run-Antwort beobachten. **Erwartung:** keine neuen Entitäten/Join-Zeilen; Counts und Detailansichten identisch.
3. Eine **Testkopie** mit zulässiger, eindeutig identifizierbarer Änderung konvertieren. Vor Apply die betroffene öffentliche Seite neu laden. **Erwartung:** alter Wert bleibt sichtbar.
4. Änderungs-Dry-run prüfen, dann Apply bestätigen. **Erwartung:** nur erwartete Änderung im Diff; danach öffentlicher Wert aktuell, ohne Neustart oder manuelles Cache-Leeren. Schreibantwort nicht als cachebarer Erfolg wiederverwendbar.
5. Falls `sync` genutzt wird, absichtlich entfernte Testzeile samt betroffenen Beziehungen prüfen. **Erwartung:** dokumentierte Sync-Semantik, keine verwaisten Links.

**Evidenz:** beide Run-IDs/Fingerprints, Diff, Tabellen-Counts, Screenshots vor/nach Commit. **Nicht bestehen**, wenn zweiter Import Duplikate erzeugt oder die Öffentlichkeit unbestätigte Änderungen zeigt.
