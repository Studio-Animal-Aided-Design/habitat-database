# UAT-M1-004 – Ungültiger Import und atomarer Rollback

**GitHub-Test-Issue:** [#127](https://github.com/Studio-Animal-Aided-Design/habitat-database/issues/127)

**Ziel:** Fehlerhafte oder manipulierte CSVs ändern den kanonischen Stand nicht. **Bezug:** #76, #107; M1-02/04. **Umgebung:** lokale Test-DB mit gültig importiertem Snapshot; Kopie der CSVs, niemals Original ändern.

## Schritte und Soll-Ergebnis

1. DB-Counts, eine repräsentative öffentliche Seite und Snapshot-Fingerprint als Vorher-Zustand sichern.
2. In der **Kopie** eine Pflichtspalte entfernen, eine Beziehung auf unbekannten Schlüssel setzen oder eine natürliche Schlüsselkollision erzeugen. Dry-run senden. **Erwartung:** strukturierte Datei-/Zeilen-/Feld-Diagnose; kein Apply möglich; DB/Seite unverändert.
3. Separat nach einem gültigen Dry-run eine staged Datei ändern oder falsche Checksumme/abgelaufene Run-ID für Apply verwenden. **Erwartung:** Apply verweigert; keine Teilübernahme.
4. Einen transaktionalen Fehlerfall mit dokumentierter Test-Fixture ausführen. **Erwartung:** alle Tabellen auf Vorher-Stand, keine teilweise veröffentlichten Beziehungen; Run-/Fehlerstatus nachvollziehbar.
5. DB-Counts und Seiteninhalt nach jedem Negativlauf erneut vergleichen.

**Evidenz:** redigierte Diagnosen, Vorher-/Nachher-Counts und Fingerprints, Seitenvergleich, Run-Status. **Nicht bestehen**, wenn Teilupdates, verwaiste Beziehungen oder ein unklarer Fehler ohne Zeilenbezug entstehen.
